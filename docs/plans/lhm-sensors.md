# Bundled LibreHardwareMonitor sensor service

The sensor migration replaces the MAHM/Afterburner collectors with a machine-wide
`Strata.SensorService` using unmodified LibreHardwareMonitorLib 0.9.6. CPU/GPU/RAM
and mounted-volume channels keep their existing widgets. New motherboard, SMART,
network and controller widgets are outside this delivery.

## Installation and development

The Windows 11 x64 NSIS installer installs into `Program Files/Strata`, includes
the .NET 10 runtime and offline WebView2 installer, and runs the official signed
PawnIO 2.2.0 installer with `-install -silent` when a compatible driver is absent.
Its SHA-256 is pinned in `sensor-service/dependencies.json`. Existing newer driver
versions are never downgraded: the installer tests loading the bundled signed
IntelMSR module before accepting an existing installation. This tests module
loading, not universal CPU sensor support.

Installation needs UAC. The service runs as LocalSystem; the bar stays unelevated.
The runtime performs no dependency downloads and needs neither the LHM GUI nor
Afterburner. PawnIO remains installed on uninstall because other applications may
use it. A requested driver reboot stops installation with a repair/retry message.

Developers need the .NET 10 SDK, Rust/MSVC, Node and pnpm. Commands:

```powershell
dotnet test sensor-service/Strata.SensorService.Tests
powershell -File scripts/build-sensors.ps1
pnpm package:windows
```

`build-sensors.ps1 -Dotnet <sdk-dotnet.exe>` accepts a private SDK. Package builds
download pinned sources, signed driver and runtime assets at build time. NuGet
lockfiles are generated by restore and enforced during publish. Source archives
include LHM, PawnIO, its modules and pinned driver submodules; package notices and
SHA-256 manifests accompany the installed files.

`package:windows` selects `src-tauri/tauri.sensors.conf.json`; that packaging-only
configuration includes service resources and installer hooks. The base Tauri
configuration builds the standalone bar without bundling, so Rust unit tests and
ordinary bar development do not require staged .NET artifacts.

`Strata.SensorService.exe --probe` samples twice and writes JSON to stdout;
`--verify-driver` only tests signed module loading; `--console` hosts the service
loop without SCM for development. The production Rust client deliberately rejects
console-hosted pipes: it verifies the server PID against the running SCM service.
The standalone bar executable therefore requires the installed service, including
in `pnpm desktop` development. Service diagnostics are included in the native
`diagnostics` command and `--probe` output.

The installer backs up service files, the previous app/uninstaller executables
and display version before replacing files. A pinned, generated NSIS template
selects in-place upgrade rather than deleting the previous installation first.
Install failure/cancellation restores the backup and previous service running
state. The next installer run recovers an interrupted transaction. Driver upgrades
are shared machine state and are intentionally not rolled back. Installation logs
are stored at `%ProgramFiles%/Strata/sensor-install.log`.

For manual recovery, run the following in an elevated PowerShell, using the script
from this checkout or the installed sensor package:

```powershell
powershell -File scripts/install-sensors.ps1 -Mode Rollback -InstallDir 'C:/Program Files/Strata'
```

## Collection and protocol

The local pipe is `Strata.SensorService.v1`. Frames contain a little-endian u32
length followed by UTF-8 JSON, capped at 1 MiB. The client sends
`{version:1,type:'subscribe',channels:[...]}` every 500 ms as a renewable lease.
Responses are `loading` or snapshots with service instance ID, monotonically
increasing sequence, observation time, per-channel hardware identity/data and
diagnostics. Unknown requests, versions, channels, fields and invalid frame sizes
are rejected. No control/write/launch methods exist.

ACLs allow authenticated local users to query the pipe, reserve instance creation
for its owner/System/administrators and reject remote clients. Rust checks the
pipe PID against SCM before transmitting. All pipe I/O runs on a dedicated thread;
the audio/transport worker only accesses a cache. Reconnect delay grows from 1 to
30 seconds. A session closes when all its subscriptions disappear.

One service collector combines subscriptions from all clients and collects each
requested group once per 2-second tick. Empty subscriptions pause hardware reads
and close LHM handles. Client disconnect/lease expiry removes demand. Device
rediscovery runs every 30 seconds, after resume notifications and on tick gaps.
A 20-second watchdog exits a blocked service so SCM can restart it; stale metrics
already become errors after 6 seconds. SCM crash recovery delays are 5/15/30 seconds.

The Rust cache validates complete frames before applying them. Repeated sequences
do not renew timestamps or append history. Fresh equal readings are new
observations. Missing metrics preserve their previous value/time as `error`;
never-seen metrics are `unavailable`. Missing disk snapshots fail at channel level.
Histories hold at most 61 points/120 seconds and reset on service instance,
hardware/sensor identity change or clock regression. No failure invokes another
collector or demo adapter.

LHM can retain `ISensor.Value` after a failed underlying read. The pinned adapter
clears the concrete internal Sensor's managed Value before calling Update and
disables LHM history. It does not touch `IControl`, parameters or hardware. The
internal writable nullable-float property is checked and tested; unsupported
implementations fail closed. Future LHM upgrades must revalidate this behavior.

## Source definitions

| Metric                     | Definition                                                                                                                                                                     |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| CPU load                   | LHM total per package, weighted by logical thread count; single-core fallback averages logical thread loads.                                                                   |
| CPU frequency              | Mean of available non-effective per-core LHM clocks, MHz converted to Hz; unavailable without clocks. This replaces PDH frequency semantics.                                   |
| CPU topology/nominal clock | Windows WMI counts and core-weighted MaxClockSpeed; these are explicit complements.                                                                                            |
| CPU temperature            | Package sensor; AMD Tdie preferred to Tctl; highest core only when package is absent. Highest selected package across CPUs.                                                    |
| GPU identity               | Largest dedicated DXGI hardware adapter; exact LHM PnP instance resolves to D3D interface/LUID. Ambiguous/missing match exposes no LHM metrics.                                |
| GPU use/memory             | LHM GPU-core usage and binary SmallData bytes. This differs from busiest PDH engine usage. Capacity uses LHM when exposed, DXGI otherwise.                                     |
| GPU thermal/power/fan      | GPU core temperature, explicitly named package/board power in watts, highest valid fan percentage. RPM is never converted.                                                     |
| RAM                        | LHM physical used/available GiB converted to bytes; total is their sum. Used includes modified pages, unlike the former Task-Manager-style subtraction.                        |
| Cache/pagefile             | Windows PDH modified + standby lists; EnumPageFiles in-use pages. No configured pagefile remains `notConfigured`.                                                              |
| Volumes                    | Windows mounted letters, drive type, labels, total/free bytes. Empty/unreadable media omitted. SYSTEM does not inherit interactive users' mapped drives. SMART stays disabled. |

Sensor metadata is `{provider:'libreHardwareMonitor',hardwareId,sensorId,name}`.
Canonical Rust contracts generate TypeScript; runtime Zod schemas and fixtures
use that identity. Units, channels and configuration stay unchanged. All source
complements are identified in service diagnostics. Driver absence is explicit;
successful DLL loading alone does not establish sensor availability.

## Acceptance and evidence

Automated checks cover selection, conversions, invalid/zero values, duplicate GPU
models, LHM cache invalidation, fragmented/oversized protocol frames, live local
pipe sharing/idle behavior, malformed clients and Rust retention/freshness/reset.
The native probe and full process accounting must include the separate service;
`scripts/measure-idle.ps1` now discovers its SCM process as well as WebView2 children.

An unprivileged probe on the available Intel/NVIDIA machine returned GPU load,
VRAM, temperature, watts and legitimate zero fan percentage, RAM and mounted
volumes without Afterburner. PawnIO is absent in this environment, so CPU
temperature and core clocks remain unavailable. This establishes partial live
coverage, not installed service acceptance.

Release gates still require a clean Windows 11 VM with elevated installation:
offline install, actual module access under LocalSystem, standard-user bars,
upgrade/rollback/repair, uninstall with shared PawnIO, driver reboot/block cases,
service crash/resume, Intel/AMD CPU and NVIDIA/AMD/Intel GPU coverage, and controlled
idle/load comparison including service costs. Unsupported hardware must be recorded
as such. Existing evidence files remain historical and are not rewritten.
